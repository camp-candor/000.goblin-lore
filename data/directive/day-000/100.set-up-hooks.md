### II. ARCHITECTURAL CONTEXT & PROBLEM STATEMENT

#### The Problem
When cloning a repository downstream (such as `000.goblin-lore` from `npm-agent-01`) or initializing a fresh workspace:
1. **Git Hook Disconnect:** Git does not serialize `.git/config` across clones. Even though the `.husky/` and `.husky/_/` hook engines are committed in source control, Git defaults to looking inside `.git/hooks/` (which only contains `.sample` files). As a result:
   - GUI Git clients (TortoiseGit, VSCode Git) and CLI `git commit` commands bypass `pre-commit` and `lint-staged` completely.
   - Changes bypass code formatting, linting, and branch validation prior to commit.
2. **Package Manager Drift:** In `bin/git-hooks/functions.sh`, the helper function `get_package_manager()` fell back to `"pnpm"` when `"packageManager"` was absent from `package.json`. Because the monorepo uses standard NPM workspaces, running pre-commit with `pnpm` produced workspace incompatibility warnings.

#### The Goal
1. Ensure the current repository automatically arms `core.hooksPath = .husky/_` whenever dependencies are installed (`npm install`) or when running `npm run setup:shield`.
2. Provide step-by-step instructions so any coding agent can reproduce this configuration on any other repository.

### III. IMPLEMENTATION SPECIFICATION (CURRENT REPOSITORY)

#### 1. Modify `package.json`

Add a cross-platform `prepare` script under the code quality / hygiene section. This guarantees that `core.hooksPath` is armed whenever `npm install` runs, while failing safely if executed in an environment without git:

```json
"scripts": {
    "prepare": "node -e \"try { require('child_process').execSync('git config core.hooksPath .husky/_'); } catch {}\"",
    "fix": "npm run fix:all",
    "fix:all": "npm run prettier:fix && npm run lint:fix",
    "lint:check": "eslint .",
    "lint:fix": "eslint . --fix",
    "lint:staged": "npx lint-staged --relative",
    "prettier:check": "prettier . --check",
    "prettier:fix": "prettier . --write"
}
```

#### 2. Modify `bin/git-hooks/functions.sh`

Locate `get_package_manager()` around line 17 and change the fallback from `"pnpm"` to `"npm"`:

```bash
get_package_manager() {
    if [ -n "${PACKAGE_MANAGER:-}" ]; then
        printf '%s\n' "$PACKAGE_MANAGER"
        return
    fi

    repo_root="$(get_repo_root)"
    node -e '
        const fs = require("node:fs")
        const packageJson = JSON.parse(fs.readFileSync(process.argv[1], "utf8"))
        const packageManager = packageJson.packageManager?.split("@")[0] ?? "npm"

        console.log(packageManager)
    ' "$repo_root/package.json"
}
```

#### 3. Modify `scripts/setup-merge-shield.mjs`

Ensure `setup-merge-shield.mjs` explicitly configures `core.hooksPath .husky/_` alongside the Git `ours` merge driver:

```javascript
// 3b. Arm Git Hooks (.husky/_)
try {
    execSync('git config core.hooksPath .husky/_', { stdio: 'pipe' });
    console.log('>> [OK] Git hooks path armed locally (core.hooksPath = .husky/_).');
} catch (err) {
    console.error(':: [FAIL] Failed to configure core.hooksPath:', err.message);
    process.exit(1);
}
```

#### 4. Arm Local Git Configuration Immediately

Execute locally via shell:
```bash
git config core.hooksPath .husky/_
```

### IV. HOW TO REPRODUCE ON ANOTHER REPOSITORY

For any new downstream repository, template, or external project, follow these sequential steps:

#### Step 1: Verify / Scaffold Hook Infrastructure
Ensure the repository has Husky v8/v9 shell dispatchers committed:
- Directory `.husky/` containing:
  - `pre-commit` (Executable bash script that calls your checks / lint-staged)
  - `pre-push` (Optional: branch / upstream verification)
- Directory `.husky/_/` containing:
  - `h` (Husky POSIX runner script)
  - `husky.sh`
  - `pre-commit` (Wrapper script: `. "$(dirname "$0")/h"`)
  - `.gitignore` (Containing `_` or ignored runtime artifacts if applicable)

> **Note:** If Husky is not yet initialized in the target repo:
> ```bash
> npx husky init
> ```
> Or copy `.husky/` and `bin/git-hooks/` directly from `npm-agent-01`.

#### Step 2: Configure `lint-staged` in `package.json`
Verify `lint-staged` is installed in `devDependencies` and configured:
```json
"lint-staged": {
    "*.{js,ts,tsx,json,css,md}": [
        "prettier --write"
    ],
    "*.{ts,tsx}": [
        "eslint --fix --no-warn-ignored"
    ]
}
```

#### Step 3: Add `prepare` Lifecycle Hook to `package.json`
Add the cross-platform Node one-liner to `scripts` in `package.json`:
```json
"prepare": "node -e \"try { require('child_process').execSync('git config core.hooksPath .husky/_'); } catch {}\""
```

#### Step 4: Ensure Package Manager Alignment
In `bin/git-hooks/functions.sh`, make sure `get_package_manager()` defaults to the correct package manager (`npm` or `pnpm` depending on repo system):
```javascript
const packageManager = packageJson.packageManager?.split("@")[0] ?? "npm";
```

#### Step 5: Arm Git Configuration in the Working Copy
Run:
```bash
npm run prepare
```
Or directly:
```bash
git config core.hooksPath .husky/_
```
