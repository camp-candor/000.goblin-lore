### II. ARCHITECTURAL CONTEXT & PROBLEM STATEMENT

#### The Problem
When cloning a repository downstream (such as `000.goblin-lore` or `000.camp-candor-cauldron`) or initializing a fresh workspace:
1. **Git Hook Disconnect:** Git does NOT serialize `.git/config` across clones or `git pull`. Even though the `.husky/` and `.husky/_/` hook engines are committed in source control, Git defaults to looking inside `.git/hooks/` (which only contains `.sample` files). As a result:
   - GUI Git clients (TortoiseGit, VSCode Git) and CLI `git commit` commands bypass `pre-commit` and `lint-staged` completely.
   - Changes bypass code formatting, linting, and branch validation prior to commit.
2. **Package Manager Drift:** In `bin/git-hooks/functions.sh`, the helper function `get_package_manager()` fell back to `"pnpm"` when `"packageManager"` was absent from `package.json`. Because the monorepo uses standard NPM workspaces, running pre-commit with `pnpm` produced workspace incompatibility warnings.
3. **The Remote Agent vs. Local Machine Boundary:**
   > **CRITICAL ARCHITECTURAL DISTINCTION:**
   > Remote coding agents (like Jules) execute in ephemeral cloud sandbox environments. When Jules modifies code and runs `git config core.hooksPath .husky/_`, that configuration ONLY takes effect inside Jules's cloud container.
   > Because Git never transmits `.git/config` through pull requests or `git pull`, **the developer's local workstation will NOT have `core.hooksPath` armed simply by merging and pulling the PR**.
   > The local machine must execute `npm run prepare` (or `npm install`) to trigger the configuration locally.

#### The Goal
1. Ensure the repository codebase contains the cross-platform `"prepare"` script in `package.json` to configure `core.hooksPath = .husky/_`.
2. Ensure `setup-merge-shield.mjs` explicitly arms `core.hooksPath`.
3. Provide explicit post-pull / local-arming instructions so human developers and local agents know to run `npm run prepare` once on their workstation.

### III. IMPLEMENTATION SPECIFICATION (CURRENT REPOSITORY)

#### 1. Modify `package.json`

Add a cross-platform `prepare` script under the code quality / hygiene section. This guarantees that `core.hooksPath` is armed whenever `npm install` or `npm run prepare` runs, while failing safely if executed in an environment without git:

```json
"scripts": {
    "prepare": "node -e \"try { require('child_process').execSync('git config core.hooksPath .husky/_'); } catch {}\"",
    "fix": "npm run fix:all",
    "fix:all": "npm run prettier:fix && npm run lint:fix",
    "lint:check": "eslint .",
    "lint:fix": "eslint . --fix",
    "lint:staged": "npx lint-staged --relative",
    "prettier:check": "prettier . --check",
    "prettier:fix": "prettier . --write"
}
```

#### 2. Modify `bin/git-hooks/functions.sh`

Locate `get_package_manager()` around line 17 and change the fallback from `"pnpm"` to `"npm"`:

```bash
get_package_manager() {
    if [ -n "${PACKAGE_MANAGER:-}" ]; then
        printf '%s\n' "$PACKAGE_MANAGER"
        return
    fi

    repo_root="$(get_repo_root)"
    node -e '
        const fs = require("node:fs")
        const packageJson = JSON.parse(fs.readFileSync(process.argv[1], "utf8"))
        const packageManager = packageJson.packageManager?.split("@")[0] ?? "npm"

        console.log(packageManager)
    ' "$repo_root/package.json"
}
```

#### 3. Modify `scripts/setup-merge-shield.mjs`

Ensure `setup-merge-shield.mjs` explicitly configures `core.hooksPath .husky/_` alongside the Git `ours` merge driver:

```javascript
// 3b. Arm Git Hooks (.husky/_)
try {
    execSync('git config core.hooksPath .husky/_', { stdio: 'pipe' });
    console.log('>> [OK] Git hooks path armed locally (core.hooksPath = .husky/_).');
} catch (err) {
    console.error(':: [FAIL] Failed to configure core.hooksPath:', err.message);
    process.exit(1);
}
```

### IV. HOW TO REPRODUCE ON ANOTHER REPOSITORY

For any new downstream repository, template, or external project, execute the following two phases:

#### Phase A: Repository Source Files (Executed by Jules / PR Bot)

1. **Verify / Scaffold Hook Infrastructure:**
   Ensure the repository has Husky v8/v9 shell dispatchers committed:
   - Directory `.husky/` containing `pre-commit` and `pre-push`.
   - Directory `.husky/_/` containing `h`, `husky.sh`, `pre-commit` (which calls `. "$(dirname "$0")/h"`), and `.gitignore`.
   *(If missing, copy `.husky/` and `bin/git-hooks/` from `npm-agent-01`).*

2. **Configure `lint-staged` in `package.json`:**
   ```json
   "lint-staged": {
       "*.{js,ts,tsx,json,css,md}": [
           "prettier --write"
       ],
       "*.{ts,tsx}": [
           "eslint --fix --no-warn-ignored"
       ]
   }
   ```

3. **Add `prepare` Lifecycle Hook to `package.json`:**
   ```json
   "prepare": "node -e \"try { require('child_process').execSync('git config core.hooksPath .husky/_'); } catch {}\""
   ```

4. **Ensure Package Manager Alignment:**
   In `bin/git-hooks/functions.sh`, ensure `get_package_manager()` defaults to `"npm"`.

5. **Commit and Merge the PR to trunk (`main`).**

---

#### Phase B: Workstation Activation (MANDATORY LOCAL STEP)

> **WHY THIS STEP IS REQUIRED:**
> Merging a GitHub PR changes files in the work tree, but **never modifies `.git/config` on the developer's computer**.

After pulling the merged PR on the local development workstation, run **one** of the following commands in the repository root:

```bash
# Option 1: Run the newly added prepare script directly
npm run prepare

# Option 2: Run a clean install (which automatically executes 'prepare')
npm install

# Option 3: Configure Git directly
git config core.hooksPath .husky/_
```
