## 1. What This Software Is

`goblin-lore` is a **deterministic narrative canon compiler and audit deck**.
You write your story world (characters, locations, items, grievances, world
laws) as plain **Markdown dossiers with YAML frontmatter**, and this software:

1. **Ingests** the Markdown corpus (your "State0" -- the immutable canonical
   source of truth held in Git).
2. **Validates** it against a strict Zod meta-ontology: integer basis-point
   math, anatomical limb capacities, spatial portal symmetry, grievance DAG
   acyclicity, epistemic firewalls, constitutional rules, and more.
3. **Compiles** the validated world into a sealed machine snapshot
   (`compiled/<series>/bible-state.json`) with a **SHA-256 Merkle root**
   (`H_root`) produced via RFC 8785 canonical JSON.
4. **Guards** the result with a **Gate 0 zero-drift tripwire**: any
   uncommitted change to `compiled/` fails the audit, guaranteeing the canon
   cannot silently drift.

The core design law (from `data/overview/Overview_ NPM-Agent.00.md`):

> "The untrusted agent proposes intents, while deterministic code disposes
> state."

In plain terms: **you (and any LLM you use to draft prose) are only allowed to
*generate* a series and edit the Markdown dossiers. All accounting of physical
reality -- hands, legs, paranoia clocks, intensities, spatial links, time --
is done by deterministic code that costs $0.00 (`T_0 = $0.00`) and fails
closed.** Impossible or contradictory fiction (e.g. a character with one arm
holding two items) is *rejected at compile time*, before you ever spend a
token, a TTS second, or a GPU frame.

The terminal cockpit is the single window into all of this. It is a full-screen
"curse" text UI (Blessed) rendered directly in your terminal.

## 2. The Mental Model: State0, Compilation, and Gate 0

Before touching the menus, hold these four concepts:

| Concept | Meaning | Where it lives on disk |
|---|---|---|
| **State0 / corpus** | The Markdown dossiers you author. The single authoritative truth. | `lore/series/<series-slug>/*.md` |
| **Series** | One story world, identified by a slug (kebab-case), e.g. `wiregrass-basin`. | Directory under `lore/series/` |
| **Compiled canon** | The deterministic, sealed machine snapshot generated *from* the corpus. Strictly disposable; safe to delete. | `compiled/<series-slug>/bible-state.json` + timestamped archives |
| **Gate 0** | A zero-drift tripwire. Verifies `compiled/` matches a fresh rebuild bit-for-bit (`git diff --exit-code compiled/`). Any unexplained change = drift = failure. | Compile flight deck option `[5]` |

The canonical cycle is:

```text
   WRITE dossiers (Markdown)
        |
        v
   AUDIT  (menu items 1-8, S, H -- all $0.00 local checks)
        |
        v
   COMPILE  (3-pass gauntlet: structural -> relational -> Merkle seal)
        |
        v
   GATE 0 (zero-drift tripwire: compiled/ must match the rebuild)
        |
        v
   COMMIT  (canon sealed in Git; H_root hash is your fingerprint)
```

Deleting `compiled/` entirely is *safe and supported* -- the
`[H] HERMETIC OFFLINE DELETION PARITY` tool exists specifically to prove the
compiler can rebuild a bit-identical `H_root` from the raw Markdown alone.

## 3. System Requirements and Installation

**Prerequisites**

- **Node.js** `>= 22.0.0` (engines field of `package.json`)
- **npm** `>= 10.0.0`
- A terminal with ANSI/color support (Windows Terminal, iTerm2, any Linux TTY).
  The UI is 7-bit pure ASCII throughout, so nothing exotic is needed.

**Install (first time only)**

```bash
git clone <your-fork-url> goblin-lore
cd goblin-lore
npm ci
```

`npm ci` installs all workspaces (`packages/*`, `apps/*`). There is no database
to configure and no cloud account needed for the lore decks -- everything
listed below runs 100% offline at zero cost.

## 4. Launching the Terminal Cockpit

The single command to launch the software:

```bash
npm run tui
```

What actually happens:

1. `apps/995.library/run.ts` compiles project references (`tsc -b 995.library
   ../../packages/<each>`) -- you will see a heartbeat log
   `>> [BUILD] Compiling references...` every 3 seconds while it works.
2. It boots the immutable Blessed harness and exposes it globally as
   `global.LIBRARY` (a `hunt(action, payload)` action dispatcher).
3. It scans `packages/` for every package with a `tsconfig.json` and terminal
   metadata (`package.terminal.globalKey / menuTitle / menuDesc`), mounts each
   one, and forces `299.lore` to the **front** of the root menu.
4. Because the script is `-t lore`, it **boots you straight into the LORE
   submenu** (not the root menu) and prints the cockpit banner.

Targeted launches are also possible:

```bash
npm run tui                 # == -t lore : boots directly into LORE MENU
npx tsx apps/995.library/run.ts            # boots into the ROOT MENU
npx tsx apps/995.library/run.ts -t library # boots into the LIBRARY MENU only
```

On successful boot you will see (streamed into the right-hand console pane):

```text
+==============================================================================+
|               GOBLIN LORE :: ONTOLOGICAL COMPILER & AUDIT DECK               |
+------------------------------------------------------------------------------+
| SERIES : 000.sample-hearth    | ENGINE : 43.compile.unit (T_0 = $0.00)      |
| STATUS : IDLE                 | H_ROOT : UNSEALED (RUN [C] TO MINT)         |
+==============================================================================+
:: [KEYS] UP/DOWN or J/K: Navigate | ENTER: Select
```

`SERIES` shows the active series slug (default `000.sample-hearth` before a
compile sets it). `STATUS` shows the compiler state. `H_ROOT` shows the
first-16/last-8 characters of the last minted Merkle root, or
`UNSEALED (RUN [C] TO MINT)` before you ever compiled.

## 5. Keyboard Controls and Screen Anatomy

**Controls (bound at boot by `run.ts`):**

| Key | Effect |
|---|---|
| `UP` / `DOWN` / `J` / `K` | Move the highlight up/down through the current choice list |
| `ENTER` | Select/execute the highlighted choice |
| `q` | Clean shutdown (clears terminal, closes screen, exits with code 0) |
| `Ctrl+C` | Same clean shutdown |
| `ESCAPE` pressed twice within 2.5 seconds | Same clean shutdown (double-tap safety) |

Note `q` and double-`ESCAPE` quit the *whole application*, not the current
submenu. To exit a submenu graph you select its built-in back option
(`ROOT MENU`, `[ BACK ]`, `[<] BACK`, `[<] RETURN TO LORE MENU`, etc.).

**Screen layout (immutable 12x12 grid dual-pane topology):**

```text
+-------------------+-----------------------------------------------+
|  LEFT PANE        |  RIGHT PANE (cns00)                           |
|  Columns 0-4      |  Columns 4-12                                 |
|  (33% width)      |  (67% width)                                  |
|                   |                                               |
|  Interactive      |  - Boot banner (SERIES/STATUS/H_ROOT)         |
|  vertical choices |  - Focus tooltips (streamed as you highlight)  |
|  rendered from    |  - Live telemetry, receipts, audit reports    |
|  98.menu.unit     |  - Compile receipts and failure redlines      |
+-------------------+-----------------------------------------------+
```

- The **left pane** is the only place you make choices.
- The **right pane (`cns00`)** is where all output lands. Deleting/altering
  this layout is forbidden by the workspace constitution.

A practical consequence: work with the menu on the left and *read the
telemetry* on the right. Every audit prints its verdict with a receipt tag
(`[OK]`, `[FAIL]`, `[PASS]`, `:: [TRAP]`...), and highlighting a choice before
pressing ENTER prints a one-line description first:
`:: <description>` -- use this to preview what a menu item does.

## 6. The ROOT MENU (Master Switchboard)

Launched only when you run `run.ts` with no `-t` target, or when you select
`ROOT MENU` from the LORE MENU.

The list is built as:

```text
1. LIBRARY MENU            <- the immutable harness's own menu
2. LORE MENU               <- forced first; this is your deck
3. ...one entry per mounted package
   (e.g. PIVOT MENU, AGENT MENU, CLOUDFLARE MENU if present)
```

- Selecting a package entry dispatches `[Menu action] Init Menu` on that
  package's mounted instance.
- Selecting an unknown/exit choice closes the terminal.
- After a package submenu completes, the master switchboard reopens
  automatically (the LORE MENU's `ROOT MENU` choice releases its resolver).

For lore work you will live in `LORE MENU`; the root menu exists as the
harness's navigation spine.

## 14. Programmatic Access (LIBRARY Dispatch) and Headless CLI

### 14.1 The dispatch pattern

Everything the menus do is also reachable from code through the same
action channel the harness uses. Books:

- Boot the library: `npx tsx apps/995.library/run.ts` exposes `global.LIBRARY`,
  and the lore deck as `global.LORE`. Both expose `hunt(type, payload)`.
- Payload shape: `{ idx, src, val, dat, slv }`; results arrive via `slv` (or
  the returned bit). All types follow the harness convention
  `'[Domain action] Verb'`.

Useful dispatches (exact types verified in code):

```ts
// Compile the whole series (what [1] does on the flight deck)
LIBRARY.hunt('[Compile action] Run Complete Gauntlet', {
    idx: 'cli-compile',
    src: process.cwd(),
    val: 1, // verbose telemetry flag
    dat: { seriesSlug: '000.sample-hearth' },
    slv: (res) => console.log(res?.resBit?.rootMerkleHash),
})

// Gate 0 with the drift tripwire enforced
LIBRARY.hunt('[Compile action] Gate 0 Verification Audit', {
    idx: 'cli-gate0',
    src: process.cwd(),
    dat: { seriesSlug: 'wiregrass-basin', verifyDriftTripwire: true },
})

// Genesis: scaffold a NEW series with YOUR config (fully custom, unlike the
// cockpit default). Dispatch these back-to-back:
LORE.hunt('[Series action] Scaffold Series Tree', {
    src: 'my-series-slug',
    dat: { seriesSlug: 'my-series-slug', config: mySeriesConfig },
})
LORE.hunt('[Seed action] Populate Genesis Seeds', {
    dat: { seriesSlug: 'my-series-slug' },
})

// Scaffold one dossier
LORE.hunt('[Entity action] Update Entity', {
    src: 'char_new_goblin',
    dat: { seriesSlug: 'under-the-floorboards', domain: 'characters',
           entityId: 'char_new_goblin', frontmatter: { id: 'char_new_goblin', type: 'character' },
           proseBody: '## Wants (surface)\nOwn a real door.\n' },
})

// Retire with matter conservation
LORE.hunt('[Logistic action] Update Logistic', {
    src: 'char_wart',
    dat: { seriesSlug: 'under-the-floorboards', entityId: 'char_wart',
           itemTransfers: { item_wart_bucket: 'char_bog' } },
})

// Append a custom errata record
LORE.hunt('[Laws action] Update Laws', {
    src: '<repoRoot>/series/<slug>',
    dat: { seriesDir: '<repoRoot>/series/<slug>', record: myErrataRecord },
})

// Stylometric lint + hermetic parity for a series
LORE.hunt('[Compile action] Stylometric Lint', {
    idx: 'cli-lint', dat: { seriesSlug: 'my-series-slug', emitTelemetry: true },
})
LORE.hunt('[Compile action] Offline Deletion Test', {
    idx: 'cli-parity', dat: { seriesSlug: 'my-series-slug', emitTelemetry: true },
})
```

Naming the legacy buzzers used by lifecycle tools (for cross-checking while
scripting): scaffold `SCAFFOLD_SERIES_TREE` (`29.series.unit`), seeds
`POPULATE_SEEDS`-style `27.seed.unit`, entity `UPDATE_ENTITY`
(`09.entity.unit`), logistic `UPDATE_LOGISTIC` (`04.logistic.unit`), status
`UPDATE_STATUS` (`32.status.unit`), laws `UPDATE_LAWS` (`03.laws.unit`). The
`slv` result bits are read by the menus from
`res?.serBit || res?.sedBit || res?.entBit || res?.logBit || res?.stsBit || res?.lawBit || res`,
so when scripting rely on the documented receipts printed to your own console.

## 16. Creative Workflow: The Most Effective Path to a Sealed Series

### Workflow A -- Authoring a brand-new series end-to-end (the golden path)

**Step 0. Orientation (5 minutes).** `npm run tui`. From the LORE MENU press
`1. VALIDATE SCHEMA INVARIANTS` once to see every audit class pass with
receipts, and confirm your environment is sound. (`>> [GATE_0:PASSED]
Primitive mathematical foundations sealed. Status code: 0.`)

**Step 1. Provision the workspace.**

- From the cockpit: select
  `[G] UNIVERSAL SERIES GENESIS WIZARD` -> it provisions
  `series/ashfall-basin/` with the canonical `LOW_FANTASY_FARCE` config plus
  the 8 directories and 3 genesis seeds.
- Programmatic (recommended for a custom slug/config): dispatch
  `[Series action] Scaffold Series Tree` + `[Seed action] Populate Genesis
  Seeds` with your own `dat` (Section 14).

**Step 2. Write the world definitions.** Edit
`series/<slug>/world/conditions.md` to declare the conditions catalog
(Section 13.2 field table): arm penalties, chronic floors, banned verbs, DSP
deltas. Define `economy.md` to your taste (keep the Byte-0 `---` preamble).

**Step 3. Cast your entities.** For each character, produce a dossier. Fastest
deterministic route: dispatch `[Entity action] Update Entity` per entity with
full frontmatter, *or* hand-write files copying the format in Section 13.2.
Respect the hard laws as you write:

- `held_items` hand count <= effective arms (condition penalties count).
- Verbs in `banned_kinetic_verbs` must match locomotion tier reality
  (`BIPEDAL_HUNCHED` cannot `SPRINT`).
- Grievances have exactly 2 participants; escalation chains must terminate
  (no cycles).
- Every portal edge in `locations/*.md` must have a reciprocal reverse edge
  (run option `[ 8. RECONCILE SPATIAL PORTAL LINKS ]`-- conceptually -- by
  dispatching the reconciler if you authored one-sided portals).
- All prose must be 7-bit ASCII and start the file with `---\n`.

**Step 4. Audit before compiling (the $0.00 loop).** In the LORE MENU:

1. `[ 26. SCHEMA & INVARIANTS ]` -> `[ 3. CONSTITUTIONAL RULE REGISTRY ]` (your
   pardons ledger, if you have one) and `[ 4. CRYPTOGRAPHIC ERRATA LEDGER ]`.
2. `[H] STATIC CORPUS HEALTH TELEMETRY` for the 4-part health card.
3. `8. INTERACTIVE SOMATIC MOTOR LAB` if you want to sanity-probe a specific
   verb against a specific body.

**Step 5. Compile + seal.** `[C] COMPILE CANON & GATE 0 GAUNTLET`:

1. `[1] RUN COMPLETE THREE-PASS GAUNTLET` -- read the receipt; fix anything
   printing `[FAIL]` and repeat.
2. `[5] GATE 0 VERIFICATION AUDIT (ZERO-DRIFT TRIPWIRE)` -- proves
   bit-identical rebuild.
3. Optional: back on the LORE MENU, run `[S] STYLOMETRIC & VOICE-BLEED
   LINTER` and `[H] HERMETIC OFFLINE DELETION PARITY` (this one deletes and
   rebuilds compiled output; only run it when nothing is mid-flight).

**Step 6. Commit the seal.**

```bash
git add series lore compiled
git commit -m "feat: seal <slug> canon at H_root <first-8-chars>"
```

Record the `H_root` from the `[SEAL:MERKLE_ROOT]` receipt; that is the
canonical fingerprint future Gate 0 runs defend.

### Workflow B -- Canonically revising an already-sealed fact (errata flow)

1. Edit the affected dossier(s) in `lore/series/<slug>/` (or the working
   `series/<slug>` machineRail copies).
2. Record the correction: dispatch `[Laws action] Update Laws` with a full
   errata record whose `superseded_*` hashes/shas reference the pre-edit
   compiled state and `active_*` reference the post-edit state (Section 11.5).
3. Re-run `[X]` from the cockpit to append the ledger entry if you prefer the
   demo path, then verify the chain:
   `[ 26. SCHEMA & INVARIANTS ]` -> `[ 4. CRYPTOGRAPHIC ERRATA LEDGER ]` ->
   expect `>> [ERRATA:OK] <slug>: N append-only record(s), head sealed.`
4. Recompile via the flight deck `[1]`, re-run `[5]`, then commit.

### Workflow C -- Casting and removing characters safely

**Add:** scaffolder or direct dossier write (Step 3 of Workflow A), then
recompile.

**Remove:** never delete a character that has items or grievances pointed at
it. Route through `[R] RETIRE CANONICAL ENTITY` (or the `[Logistic action]
Update Logistic` dispatch) with an `itemTransfers` map so every `held_item`
moves to a surviving owner; the dossier then relocates to
`characters/_retired/` and its id disappears from active drafts.

**Verify:** after any retirement, gate on
`6. AUDIT GRIEVANCE DAG & DYADIC MESH` (no newly isolated actors) and the
health card `[H]` (dyadic coverage stays at 10000bps).

### Workflow D -- Debugging a compile failure

1. Read the failure redline: `:: - [<gate>] <message> (<targetFile>)`.
2. Map gate names to their audit tooling:
   - `BYTE0`/`SCHEMA`/`SAT` -> LORE MENU `1.` and submenu
     `[ 1. VALIDATE ENTITY MANIFESTS ]`
   - `FK`/`DAG`/`PORTAL` -> LORE MENU `5.` and `6.`
   - `CLUE` -> LORE MENU `7.`
   - `ASCII` -> check the named file for non-7-bit bytes (dashes, emojis,
     smart quotes are the usual suspects)
3. Fix the exact dossier named in the receipt, then re-run `[1]`.
4. If the file is fine but output looks stale, use `[H] HERMETIC OFFLINE
   DELETION PARITY` to force a clean rebuild.

### Workflow E -- Teaching / demoing the system at zero cost

The entire DSP hub (Section 9) is purpose-built for demonstration with zero
side effects: walk through `[9] RUN FULL SOMATIC DSP VERIFICATION SWEEP` first
(certification), then each inspector live. Nothing you press there can harm
your corpus.

## 18. Troubleshooting, Known Quirks, and Drift Notes

**D1. README.md is stale template boilerplate.** It describes the worker/
995.library/100.agent template lineage. For the lore engine, this document
(005) plus `data/doc/000..004` are the accurate record.

**D2. Duplicate character files in root `series/`.** Both `wart.md` and
`char_wart.md` exist (byte-duplicates) in `under-the-floorboards`, and
unprefixed `spleen.md`, `johnny_walkman.md` etc. exist in `wiregrass-basin`.
Character discovery canonicalizes unprefixed names to `char_<name>` internally,
so scans see both spellings of the same entity while they remain on disk.
Prefer deleting the unprefixed duplicates when you touch those directories.

**D3. Missing root scripts.** `check:env`, `check:ingress`, `check:hydration`,
`release:seal` point at `scripts/*.mjs` files that do not exist (Section 15).
Not related to lore operation.

**D4. Compile source vs working corpus.** The compiler seals `lore/series/<slug>`
and falls back to `lore/series/000.sample-hearth` if the requested slug is not
found there. `series/` (root) is the machineRail working corpus used by the
lifecycle tools and ledger extraction. In practice: **author machineRail
dossiers under root `series/`, then mirror the flat-schema views you want
sealed under `lore/series/`** (or dispatch a compile with `src` pointed at a
specific directory -- `resolveSeriesDirectory` accepts an explicit scratch
path that is not a repo root). Expect a compile of a slug that exists only in
root `series/` to silently seal `000.sample-hearth` instead: check the
`[COMPILE:COMPLETE]` series name on the receipt every time.

**D5. Lifecycle tools run on defaults from the cockpit.** Because the menu
loop supplies only the active-series context, the mutating lifecycle tools
(Genesis/Scaffold/Retire/Errata) exercise their built-in demo payloads when
invoked interactively. For real authoring with your own ids, use the
dispatch route in Section 14. Verify afterwards what actually happened by
reading `series/` (and the receipts) rather than assuming.

**D6. Quitting nested loops.** There is no ESC-to-back binding. The only EXIT
paths are the explicit choices (`ROOT MENU`, `[ BACK ]`, `[<] BACK`,
`[<] RETURN TO LORE MENU`, `[ 0 ]` etc.). ESC ESC at any moment exits the whole
application.

**D7. `q` is quit, not next.** Pressing `q` inside a choice list exits the
cockpit (clean shutdown) -- do not use `q` to advance rows; use UP/DOWN/J/K.

**D8. First launch compile time.** The boot compile (`tsc -b` of every
workspace) can take a minute or more on cold caches; the heartbeat
`>> [BUILD] Compiling references...` every 3 seconds is normal. Do not close
the terminal during this phase; subsequent launches are faster.

**D9. Errors in the right pane only.** If a submenu crashes mid-operation,
the cockpit prints `:: [MENU_FAULT] <message>` into `cns00` and keeps running.
Re-enter the choice and read the pane before reopening the app.
