### Extreme Detail Execution: Implementing the Invariant Schema Core (packages/299.lore/26.schema.unit / schemas/)

To implement the Invariant Schema Core for `goblin-lore`—the system's absolute offline legislative authority operating at $T_0 = \$0.00$—we must build a strict, mathematically sound Meta-Ontology using Zod, paired with a deterministic 7-file reactive unit harness. This engine guarantees that impossible actions (e.g., a character with a severed arm wielding a two-handed weapon) are physically rejected before LLM or GPU inference is ever invoked.

Here is the exhaustive, nuanced architectural specification for building this core.

### I. The Pure Zod Meta-Ontology (`schemas/`)

[details](./002.pure-Zod-Meta-Ontology.md)

The schemas must forbid floating-point values to ensure deterministic cross-platform reproduction (IEEE 754 variances). All severities, capacities, and physical dampening metrics must be mapped to **Integer Basis Points** ($0$ to $10,000$ bp, where $10,000 \equiv 1.0$).

#### 1. The Tripartite Character Vector (`schemas/character.schema.ts`)

The `CharacterSchema` must be segmented into three absolute state vectors.

- **A. Somatic Vector (Physical Reality)**
  - `arms_available`: `z.number().int().min(0).max(4)`
  - `legs_available`: `z.number().int().min(0).max(4)`
  - `locomotion_tier`: `z.enum(['BIPEDAL_NIMBLE', 'BIPEDAL_HUNCHED', 'BIPEDAL_LIMPING', 'IMMOBILE'])`
  - `somatic_strain_bp`: `z.number().int().min(0).max(10000)`
  - `debuffs`: Array of condition pointers (e.g., `cond_brachial_plexus_severed_left`).
  - `banned_verbs`: `z.array(z.enum(["SPRINT", "VAULT", "LEAP", "BIMANUAL_LIFT", "STRANGLE"]))`. If the runtime AST selects a verb in this array, the compiler trips an unrecoverable invariant violation.
- **B. Logistical Vector (Economy & Load)**
  - `weight_capacity_bp`: Base lifting constraint.
  - `held_primary` & `held_secondary`: `z.string().regex(/^item_[a-z0-9_]+$/).nullable()`
  - `worn_gear`: `z.record(z.enum(["head", "chest", "belt", "feet"]), z.string().regex(/^item_/))`
- **C. Epistemic Vector (Knowledge & Strain)**

  - `paranoia_baseline_bp`: Base recovery point.
  - `ignorance_firewalls`: `z.array(z.string().regex(/^mystery_/))` (Secrets this character is strictly forbidden from referencing).
  - `strings`: `z.record(z.string().regex(/^char_/), z.number().int())` (Directional leverage over other characters).
  - `refusal_vectors`: Triples defining when a character will balk: `z.object({ trigger: z.string(), mandatory_refusal: z.string(), unavoidable_cost: z.number().int() })`.

### II. The Unit Architecture Implementation (`packages/299.lore/26.schema.unit/`)

The reactive schema unit enforces these Zod schemas and processes invariants dynamically.

#### 1. Interfaces & Action Bit Contracts (`fce/schema.bit.ts` & `schema.action.ts`)

Define the communication interface for the Schema unit.

// packages/299.lore/26.schema.unit/fce/schema.bit.ts

  src?: string;       // Entity type (e.g., "character", "grievance")
  val?: number;       // Status integer (0 = OK, -1 = Error)

#### 2. The Invariant Solvers (`buz/schema.buzz.ts`)

The `schema.buzz.ts` module hosts the core SAT solvers and invariant evaluations.

- **`validateEntity(cpy, bal, ste)`**: Maps `bal.src` to `SCHEMA_ROUTER`. Parses the payload via `schema.safeParse(payload)`. Failure constructs strict `[path]: message` output into `lst` and fails closed (`val: -1`).
- **`solveSomaticSAT(cpy, bal, ste)`**:
  - Calculates `netArmsAvailable = Math.max(0, arms_available - totalPenaltyArms)`.
  - Iterates through items in `held_primary` and `held_secondary`.
  - Sums the `occupies_hands` constraint (defaulting to 1).
  - Enforces the mathematical invariant: `requiredHands <= netArmsAvailable`.
  - If violated, emits `[SOMATIC_OVERLOAD]` and instantly aborts upstream compilation.
- **Deep Immutability Gate**: The payload resolved from `schema.safeParse` must be passed through a recursive `deepFreeze()` before being stored in the `StateModel`. This forces `TypeError` on any downstream script attempting to mutate physical reality.

#### 3. Integration into the 3-Pass Compiler Gauntlet

The `schema.buzz.ts` unit feeds directly into the offline compiler (`scripts/compile.ts`):

- **Pass 1**: Calls `validateEntity` on every Byte-0 YAML frontmatter parsed.
- **Pass 2**: Foreign Key Resolution. The `SchemaModel` builds a memory index isolated by `series_slug`. Dangling pointers (e.g., a `held_primary` item that doesn't exist in `/possessions`) are strictly evaluated here. DFS cycle detection ensures that `spawns_on_max_escalation` grievance chains do not loop.
- **Pass 3**: Canonical JSON Seal.
  1. Recursively sort all object keys by UTF-8 code point.
  2. Apply Unicode Normalization Form C (NFC) to all strings.
  3. Assert zero ambient time (`Date.now()` is disallowed).
  4. Hash the UTF-8 bytes to compute $H_{\text{root}}$ (SHA-256).
  5. Atomic Save: Write to `compiled/bible-state.json.tmp_[UUID]` and execute POSIX `fs.renameSync` to ensure no corrupted partial-buffer reads occur.
