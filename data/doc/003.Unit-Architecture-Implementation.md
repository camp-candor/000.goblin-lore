### Conceptual Architecture: The Reactive Schema Unit

The Schema Unit functions as the sovereign legislative checkpoint within the narrative simulation framework. Positioned inside the domain package topology, it translates abstract physical, biological, and relational laws into deterministic runtime gates. Operating under the economic mandate of catching contradictions before downstream compute is spent, the unit enforces that no entity, event, or physical action enters the canonical ledger unless it satisfies all structural invariants.

The unit is strictly decoupled from presentation frameworks, graphics renderers, audio synthesis models, and operating system clocks. It operates as a pure, memory-isolated state evaluator governed by the seven-file functional unit pattern.

### The Seven-File Unit Anatomy and Structural Contracts

Every domain unit across the architecture adheres to a strict seven-file separation of concerns. This separation establishes a unidirectional pipeline where state transformations are mathematically pure, side effects are quarantined into asynchronous routines, and communication occurs through standard ephemeral envelopes.

#### 1. The Ephemeral Communication Bit Contract

Communication between disparate units or external coordinators occurs through transient execution payloads termed Bits. The Schema Bit defines the standard boundary envelope for all schema interactions:

- **Monotonic Identifier Index:** A discrete address tag binding the message to a specific operation within the reactive pipeline.
- **Entity Type Discriminator:** A nominal discriminator string classifying the entity family being evaluated (such as characters, topological locations, material possessions, dyadic grievances, or epistemic mysteries).
- **Status Exit Code:** An integer outcome signal strictly enforcing a binary gate. A value of zero represents absolute invariant compliance. A value of negative one flags an invariant breach, immediately tripping a fail-closed execution halt.
- **Staged Payload Buffer:** An untrusted data container carrying the ingress dictionary, frontmatter attributes, or boundary query parameters awaiting validation.
- **Diagnostic Trace Array:** An ordered list of human-readable diagnostic strings detailing the exact schema path, offending value, and violated invariant rule.
- **Asynchronous Resolver Callback:** A completion function invoked to return execution results and error telemetry back to the caller.

#### 2. The Persistent Unit State Contract

While the communication bit exists only for the duration of a single operational turn, the Schema Interface governs the long-term, in-memory state slice held by the model container:

- **Unit Key Identifier:** A fixed structural token anchoring the unit inside the master state registry.
- **Historical Bit Cache:** A key-value dictionary indexing past execution bits for replayability and forensic audit trails.
- **Validated Entity Repository:** An in-memory storehouse containing entities that have successfully cleared structural parsing and invariant validation.
- **Last Validation Report:** A diagnostic structure recording the aggregate status, error manifests, and the total tally of certified entities processed during the latest compilation cycle.

#### 3. State Model Container

The Schema Model class instantiates the default baseline state for the unit. It initializes empty storage dictionaries for validated entities, sets the default status counters, and ensures that upon engine instantiation, the schema slice exists in a predictable, uncorrupted initial condition prior to receiving directives.

#### 4. Action Envelopes and Command Classes

State mutations are never applied through ad-hoc method calls. Instead, every request is wrapped into an explicit Action instance. The action layer establishes discrete class constructors for:

- **Unit Initialization:** Prepares the in-memory state slice and verifies baseline configurations.
- **Unit Configuration Update:** Reconfigures unit parameters or updates operational tolerances.
- **Entity Validation:** Encapsulates an untrusted payload for routing through the schema validator.
- **Somatic Satisfiability Proof:** Encapsulates a character's physical state and proposed inventory load to verify biological capacity.

#### 5. Asynchronous Buzzers and Execution Handlers

All business logic, schema resolution, and analytical satisfiability solvers reside within dedicated buzz routines. Buzzers receive the working copy of the model, the dispatched action bit, and the global simulation state reference. Buzzers never perform direct mutations on shared references; instead, they resolve their computations and signal completion through the bit's callback.

#### 6. Buzzer Facade Barrel

The buzzer barrel serves as a clean export boundary. It re-exports individual asynchronous handlers and provides standard synchronization routines, shielding the rest of the unit from the internal organization of specific solver algorithms.

#### 7. State Reduction Switchboard

The Reducer function acts as the deterministic coordinator. Utilizing deep cloning on every pass, it creates an isolated duplicate of the model state before evaluating incoming actions. It inspects the action type, routes the payload to the corresponding buzzer or synchronous state fold, and returns the modified state slice. This guarantees that state transitions remain predictable, unidirectional, and free of side-channel memory leaks.

### Core Algorithmic Solvers and Invariant Engines

The operational strength of the Schema Unit lies within its asynchronous solver routines. Rather than acting as passive schema decorators, these solvers execute active mathematical proofs against proposed narrative states.

#### The Entity Validation Engine

The entity validator acts as the primary gatekeeper for raw frontmatter data extracted from text files:

- **Discriminator Routing:** Inspects the source family attribute on the incoming bit to locate the authoritative schema contract.
- **Strict Permutation Rejection:** Validates incoming payloads using closed-set checking. Any property hallucinated by an upstream language model or entered erroneously by an author that is not explicitly declared in the schema triggers an immediate validation termination.
- **Diagnostic Formatting:** If validation fails, raw errors are recursively extracted and mapped into formatted strings showing the exact dot-notation field path followed by the failure rationale. The bit is marked with an error status and returned immediately, terminating the current ingestion pipeline.
- **Storage Ingestion:** If parsing succeeds, the certified entity is written to the validated entity repository inside the state model, and a success status is returned.

#### The Somatic Hand-Capacity SAT Solver

Narrative integrity collapses when characters perform physical actions that defy their bodily state. The somatic solver evaluates biological satisfiability as an explicit mathematical inequality:

- **Net Functional Limbs:** Calculates available limbs by taking the baseline anatomical count (such as standard functional arms) and subtracting penalties imposed by permanent conditions, wounds, or structural traumas. If injuries exceed baseline anatomy, the count clamps strictly to zero.
- **Load Evaluation:** Examines all material items declared in active manipulation slots (primary hand and secondary hand). It tallies the required hand occupancy values for all held equipment.
- **The Biological Invariant:** Asserts that the total required hands for all held items must not exceed the net available functional limbs.
- **Fail-Closed Overload:** If the required hands exceed available limbs, the solver appends an explicit somatic overload error to the trace array, flags the operation with a failure status, and prevents the state update from committing.

#### The Deep Immutability Gate

In-memory data corruption often occurs when a downstream script or runtime isolate accidentally mutates an ingested object reference. The Schema Unit eliminates this failure mode through recursive in-memory heap freezing:

- **Recursive Property Traversal:** Inspects every object and nested dictionary within a validated data tree.
- **V8 Heap Locking:** Freezes each level of the structure, preventing properties from being added, deleted, or reassigned.
- **Fatal Mutation Deterrence:** Any downstream runtime process that attempts to write directly to a validated entity in memory triggers a fatal system type error. This guarantees that entities stored in the unit model represent unalterable truth.

### Architectural Roles and Upstream-Downstream Integration

#### Role in the Three-Pass Compiler Pipeline

The Schema Unit provides the underlying execution mechanics for the offline compilation pipeline:

- **Pass 1 (Structural Validity and Invariant Checking):** The compiler reads source files from disk, strips metadata headers, and dispatches each entity through the Schema Unit's validation action. Scalar bounds, integer basis points, and closed kinetic verbs are locked here.
- **Pass 2 (Relational Graph Integrity):** The unit's validated entity store serves as the authoritative lookup index. The compiler verifies that foreign keys point to certified entities, confirms that grievance causal chains are acyclic, and evaluates epistemic clue-lemma disjointness rules.
- **Pass 3 (Deterministic Sealing):** Once all entities pass unit validation, the data is canonicalized, sorted, stripped of ambient time, and hashed into an immutable Merkle root.

#### Role in the Simulation Bus and Terminal Cockpit

Beyond offline compilation, the Schema Unit integrates directly into the live development cockpit:

- **Registration in the Central Manifest:** The unit is registered within the central domain manifest, binding its reducer and action listeners to the simulation state dispatcher.
- **Terminal Cockpit Control:** Operators working within the terminal curses interface can dispatch schema inspection actions directly from the menu system.
- **Real-Time Telemetry:** Validation results, diagnostic failure traces, and satisfiability receipts stream directly to the terminal's console panel. Passing validations are rendered in green telemetry frames, while invariant violations stream in high-visibility red frames, giving showrunners instant visual confirmation of narrative integrity.
